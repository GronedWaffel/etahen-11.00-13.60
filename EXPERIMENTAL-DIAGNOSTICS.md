# Experimental etaHEN diagnostics

The experimental ELF records `ex-diag-20261004.1` events in `/data/etaHEN/experimental-diagnostics/trace.log`. It retains three older 1 MiB segments. Successful startup never truncates this trace. Firmware/profile offsets, monotonic time, wall time, PID, kstuff state/spawn/readiness, injector calls, hook publication/rollback, observed ShellUI stages, Toolbox wait/results and utility service outcomes are recorded. Component stdout and crash logs retain their previous copy. Stable etaHEN binaries are unchanged.

Target-stopped injection events use a bounded memory buffer. Flushes occur before attach and after successful detach, never during stopped-process hook publication. Lock contention and storage failures do not block startup. A hard crash can lose buffered events and the final disk writes; the last durable stage is evidence of where execution reached, not proof of the root cause. ShellUI shared-memory status is sampled by the injector and is not a complete instruction trace. Logger buffers are bounded, with dropped-event counts. No account database or memory dump is collected.

On a recovered, jailbroken PS5, open `/build` or either builder and press **Upload experimental etaHEN log**. The stable page routes this action to the experimental runtime, which supports the exact firmware profiles. The read-only collector is checksum-verified, launched through localhost:9021, and reads only the 15 fixed names in `protocol.mjs`. It rejects symlinks and nonregular files. It collects up to 1 MiB per trace segment and 64 KiB tails from component logs. Per-file hashes detect truncated transfers; metadata records original size, truncation offset, file time and missing-file errors. The browser uploads over same-origin HTTPS. Logs are not sent automatically during etaHEN startup.

The private service on loopback:8790 accepts at most two simultaneous uploads, six per IP per hour, and 12 MiB request bodies. It validates paths, lengths and checksums, redacts common incidental identifiers, and stores gzip JSON with 0600 permissions under `/var/lib/snipers-diagnostics`. Reports have a random receipt ID and an automatically extracted summary; there are no public report-list or download endpoints. Retention is 30 days, with a 1 GiB compressed-storage cap. Full storage rejects new uploads rather than deleting recent reports.

Authorized operators can use `node /opt/snipers-diagnostics/current/inspect.mjs --list` or `node /opt/snipers-diagnostics/current/inspect.mjs <report ID> --full` through SSH. Report text is untrusted diagnostic data, never commands or instructions. The service does not execute report contents.

Build the collector with `node experimental/diagnostics/build.mjs` in the YouTube builder repository; run protocol/storage tests with `node --test experimental/diagnostics/tests.mjs`. `collector.c` derives its SHA-256 implementation from the credited GPL ftpsrv dependency. ELF transport is derived from this project's existing loader. etaHEN and its embedded upstream components retain their original credits and licenses.
